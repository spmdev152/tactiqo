# GitHub Review
Prioritize real defects and regressions. Check Django Ninja boundaries, ORM query behavior and N+1 risks, repository usefulness, Sportmonks rate-limit/caching behavior, statistics/odds/prediction availability handling, idempotent Celery tasks, Next.js Server/Client Component boundaries, native data fetching usage, TypeScript correctness, React Doctor findings for changed frontend code, numpydoc/TSDoc quality where required, Docker/environment impact, branch naming, commit convention, CI compliance, and test placement. Backend tests must remain in top-level `tests/` beside `manage.py`; frontend tests must remain in `src/tests/`; flag colocated test/spec files in functional source directories. Reject unnecessary abstractions and unrelated scope expansion.

Verify that frontend and backend dependency changes update and preserve the committed `bun.lock` and `uv.lock` files respectively, and that documented/CI commands use Bun and uv consistently. Verify dependency placement: frontend runtime packages in `dependencies` and development-only tooling in `devDependencies`; backend runtime packages in `[project].dependencies`, with development tooling split into uv groups `lint`, `typecheck`, and `test` and aggregated by `dev`.

Do not raise style-only findings for shadcn/ui-generated `src/components/ui/**` or Django-generated `**/migrations/**`. Review migrations for correctness, safety, dependencies, and reversibility instead.

Do not treat every React Doctor finding as automatically blocking. Require fixes for findings that materially affect correctness, performance, accessibility, security, or maintainability, and reject refactors that only add complexity to satisfy a diagnostic mechanically.

Treat the four non-negotiable style rules in `.omp/AGENTS.md` as blocking review findings. Flag any project-authored Python or TypeScript file that opens with a comment or module docstring not attached to a declaration, while accepting declaration-attached numpydoc/TSDoc, a `#!` shebang on a genuinely executable script, and TypeScript triple-slash directives. Flag any test whose documentation is not exactly the three lines `GIVEN ...`, `WHEN ...`, `THEN ...`, and accept ordinary concise documentation on fixtures, factories, helpers, and stubs. Flag any multi-line statement or expression that is not separated by a blank line from the statement above and below it, unless it opens or closes its block or the formatter removes the blank line. Flag any statement that binds a newly constructed object or value and is immediately followed by a non-binding statement without a blank line, such as a `Celery` app configured on the line after its construction; do not raise findings for consecutive bindings or for consecutive method calls, attribute mutations, and registrations against an already-bound object.
