# QA
Enforce deterministic tests without live Sportmonks calls. Backend gates run through uv and include Ruff and Pyright for project-authored code while excluding `**/migrations/**`, plus pytest/pytest-django, migration consistency, and relevant numpydoc quality checks when configured. Frontend gates run through Bun and include Prettier for project-authored code while excluding `src/components/ui/**`, plus TypeScript, Vitest, React Testing Library tests where applicable, React Doctor for changed React/Next.js code, build checks, and TSDoc validation when configured. Verify reproducible installation from committed `uv.lock` and `bun.lock` files. Verify dependency classification as part of quality review: frontend runtime packages in `dependencies`, development-only tooling in `devDependencies`; backend runtime packages in `[project].dependencies`, with development tooling split into uv groups `lint`, `typecheck`, and `test` and aggregated by `dev`. Verify API contracts, missing-data states, caching behavior, and environment-safe configuration. Enforce test isolation: backend tests belong in top-level `tests/` beside `manage.py`; frontend tests belong in `src/tests/`; functional source directories must not contain colocated test/spec files.

React Doctor findings are advisory quality signals, not an excuse for mechanical refactors. Escalate or fix findings that materially affect correctness, performance, accessibility, security, or maintainability, and ignore noise that would only add unnecessary abstraction.

Enforce the four non-negotiable style rules detailed in `.omp/AGENTS.md`. Project-authored Python and TypeScript files must not open with a file-header comment or module docstring, while declaration-attached numpydoc/TSDoc stays required. Every backend and frontend test must carry exactly three documentation lines, `GIVEN ...`, `WHEN ...`, `THEN ...`, and nothing else; fixtures, factories, helpers, and stubs in the test tree keep ordinary concise documentation instead. Every multi-line statement or expression must be separated by a blank line from the statement above and below it unless it opens or closes its block. Every statement that binds a newly constructed object or value must be followed by a blank line unless the next statement is another such binding; do not report consecutive bindings or consecutive operations against an already-bound object as violations, and treat formatter-forced layouts as exempt. Exclude generated/vendored `**/migrations/**`, `src/components/ui/**`, and `next-env.d.ts` from these style gates.
